# H3 多标的量化研究系统：固定骨架、可插拔模块与按标的选择稳健参数 v0.1

> **状态：架构契约 / DESIGN SPEC，非已部署的跨标的回测引擎，非实盘指令。** 2026-11-13 冻结研究设计。原 H3、A/B v1.0、SMA A2 V1、EMA V2/V3 的源代码和历史账本均不修改。机器可读的研究**规范**在 [h3_cross_asset_research_framework_v0_1.json](../../research/config/h3_cross_asset_research_framework_v0_1.json)，不是已经运行的策略 JSON 配置。
>
> 目标不是「遍历所有系数，找到每个标的历史最大CAGR」，而是研究：**能否复用相同的趋势/风险状态机，只对少量有明确经济意义的自由参数，在不同标的上选择经检验的稳健区域**，保留失败结果、未知状态和跨行情验证记录。

## 一、系统组成：交易引擎和研究引擎分离

```text
本地合法获得、调整口径一致的市场数据
    ↓ 交易日历、分红/拆分/货币/缺口、数据版本/哈希校验
按完成时间计算的特征层
    ├─ 日线 EMA5/10/20/60、ATR(N)、价格结构
    ├─ 上一个已完成月 EMA5、月斜率闸门
    └─ 前一已完成周 RV / 当前收盘已知 RV20（研究状态）
    ↓
[固定 H3 趋势状态机]  <-- 同一个标的必须先原样复现可比较的H3
    ├─ 原常规20/60金叉与 FAST 10/20 恢复
    ├─ 月线原闸门及延期入场状态
    ├─ 动态N20、买入首日亏损保护、净7%收盘保护
    └─ EMA20/60慢死叉；原卖出指令优先
    ↓
[可选新入场实验层]  <-- 不默认启用；新增早入场必须重算完整H3持仓/退出
    └─ EMA20/60接近但未金叉、掉头后FAST再金叉（待更多样本）
    ↓
[仓位与止盈保护]  <-- H3 shadow + actual portfolio 双状态；原H3退出仍有效
    ├─ 无叠加：H3
    ├─ 冻结A：EMA5/20死叉保护利润
    ├─ 冻结B：A + EMA10>20 + 3日下跌/ATR20>=1.5
    └─ 独立B-参数实验：ATR_N & 阈值K（不改写冻结B）
    ↓
真实账户模拟：次一正常开盘执行、手续费、现金、持仓、税/滑点情景
    ↓
对照：H3 / A / B / Buy&Hold；按标的、年份、波动阶段、交易窗口
    ↓
稳健性验证：邻域参数、不同年份、滚动训练-验证、跨标的、独立前瞻
    ↓
研究注册表：SUPPORTED / INCONCLUSIVE / REJECTED / NEEDS_OOS / PAPER_ONLY
```

**两个不同的状态机不能混写**：

1. **改变 H3 的入场**（例如近金叉失败后新增FAST进场）：会改变实际买入价、N20年龄、后续止损与全部交易资格；必须**真正重新跑整个H3状态机**。不能拿一个提前买点替换旧交易账本后宣称 CAGR/MDD。
2. **A/B 利润保护叠加层**：必须维持**原 H3 影子持仓**。特别卖出不会重置影子H3的N20、月线、FAST状态；影子H3计划退出必须优先。A/B同一窗口各最多1次额外卖出和1次特别买回。这是不同于「新入场」的 overlay 机制。

因此**在 v0.1 阶段只允许隔离对照**。把新入场形态 + B×不同ATR组合同时打开，属于之后的新联合版本（需要重新运行、测试交互），不是两项测试利润可以直接相加。

## 二、模块与参数治理：先限制自由度

| 层 | 标准对照/默认 | 第一批可研究参数 | 目前决定 |
|---|---|---|---|
| 核心 H3 | **原冻结 H3**，日EMA20/60与 FAST10/20、延期月线门槛、N20等完整规则 | 初期不对H3均线周期、N20等做自由网格 | 冻结为**跨标的比较的母体**，不声称已对所有标的最佳 |
| 新入场候选 | **关闭**；日EMA20从下方靠近EMA60、没有金叉、拉开并自身下降、后面FAST10/20新金叉 | “近”的距离/ATR、观察窗、回落幅度/ATR、再拉开幅度/ATR | **事件研究阶段，尚未升级** |
| Profit Guard | H3无叠加 / **A v1.0** / **B v1.0** 三个独立对照 | 第一层只选NONE/A/B三个离散模块 | A/B仍是**冻结研究候选** |
| B幅度判断 | B v1.0：最近3日收盘跌幅 / `ATR20` >=`1.5` | `ATR_N` 的 N={14,20,30}，K={1.0,1.5,2.0} | **有全账户敏感性数据，可以跨标的验证** |
| B获利触发阈值 | 峰值完成收盘浮盈≥10%；当前盈利且EMA20>60 | `peak_profit_min` 未来可试，但**不与ATR一起同时调** | 暂时固定 |
| 特殊再买回 | 新EMA5/10金叉、原H3影子仍长仓、EMA20>60 | `reentry_enabled` true/false 可另立消融 | 冻结A/B为true；取消特别买回不能未经测试就声称更好 |
| 交易次数 | 每个原H3窗口 1次额外卖出/1次特别买回 | 未来可做0/1等离散消融 | 暂时固定；多次卖买以前有劣势样本 |
| 波动率状态 | RV20、已完成周RV，仅作为描述/诊断 | 将来研究下单过滤或风险仓位 | 当前**禁止以RV直接替代月线gate** |
| 仓位 | 研究基准是现金/全仓 | `max_fraction`、目标波动、资金风险预算 | **另一个实验层**，不能靠改变仓位掩盖入场问题 |
| 执行与成本 | 收盘信号→次日正常开盘；单边0.05%，无息现金 | 做滑点/费率/现金利息的**场景敏感性** | 时间因果与撮合语义固定；费用不可偷换 |

### 已知研究事实，不是自动采纳的新参数

- QQQ H3本身：历史 CAGR约9.89%，MDD约−24.30%；A v1.0约10.69% /−23.94%，B v1.0约11.01%/−24.30%。QQQ 2000-01-03～2026-11-11，初始$100,000，0.05%单边费用、现金不计息。
- B的ATR扫描（14/20/30 ×1.0/1.5/2.0）9组样本内CAGR约10.85%–11.66%，最高的是 **ATR30×1.5，约11.66%**，但没有真正的独立OOS验证，不是将B改写为ATR30的理由。
- 新的“EMA20/60从下方靠近、却没有金叉、EMA20自行掉头下降、之后FAST再金叉”完整宽松形态：QQQ本样本**仅2笔**，均事后上涨，样本远不足；简单的“曾经接近”46笔或“接近后间距变大”30笔**没有高于普通FAST金叉的盈利胜率**，不应作为月线豁免条件。
- A/B历史相对收益确实有阶段依赖，但只有**14个原H3交易窗口**出现真正不同的提前保护卖出行为；高波动偏向B的全历史结果被2001/2002少数大交易影响，2020高波动A更好。因此 **波动高自动切B** 还不能作为可靠模块。
- 尽管B在某些年份收益略高，**冻结B在该样本没有把MDD降至比H3更低**；回撤仍约−24.30%。

## 三、多标的研究：区分参数迁移和逻辑迁移

| 研究对象 | 标的特征假说（须验证） | 处理方式 |
|---|---|---|
| **QQQ** | 科技和成长权重较大，有较快趋势恢复和深回撤阶段 | 当前**已反复研究的训练/发现集**；不能再宣称2000–2026是未看过的OOS |
| **SPY** | 行业覆盖更广，与QQQ的涨跌组成不同 | 使用同一核心H3/冻结A/B与B ATR网格，单独复现；**SPY与QQQ高度受共同美国股市因素影响，不算完全独立样本** |
| **日经225** | 日本市场结构、交易日历、日元、本国节假日和长期行情周期与美股不同 | 先明确是指数点位还是**真实可交易的日经追踪ETF**；交易收益必须用实际ETF的复权价格与费用，不可用指数点位伪造成可交易持仓 |
| **TQQQ** | 每日复位杠杆、路径损耗、极端回撤远大于QQQ | **单独风险家族**，不得照搬QQQ在场比例、止损或直接把收益乘3 |
| **QQQI** | 期权收益/分配机制不同，分红不等于总收益 | **单独总回报/分配验证家族**，不得照搬QQQ的长期增长或技术阈值 |

**跨标的统一的是“交易行为和归因方法”，不是价格数值。** EMA差距、ATR等要用各标的同口径价格/ATR归一化。对于刚上市的ETF，如有经授权、成分连续一致的相关指数历史，可用于**信号预热或历史诊断**，但不能假装ETF在上市前可按指数点位成交。也不把EMA200设成所有标的的硬门槛。

每个市场的预处理字段至少：`instrument_id`、`currency`、`trading_calendar`、`timestamp_timezone`、`adjustment_policy`、`price_total_return_or_price_only`、`expense_ratio`、`fund_launch`、`history_start`、`warmup_days`、`source_hash`、`tradeable_proxy`。不能在缺少价格、汇率或分红时自动凑信号。

## 四、实验流程（系统开发的真实顺序）

### 阶段0：先复现、不调参

同一标的，数据冻结后跑无叠加H3、A v1.0、B v1.0和买入持有；交易日期、信号原因、仓位、完整账户权益能够独立逐日对账。若原研究版本不适用短历史，标记 `INSUFFICIENT_HISTORY`，不自动回填不存在的历史。

### 阶段1：ATR的单层参数敏感性

对于每个有足够真实历史的标的，仅改变B退出条件的`ATR_N`和`K`，依次检查候选九宫格：

```text
N = 14 / 20 / 30
K = 1.0 / 1.5 / 2.0
其余 H3 / B 的出入场、最高浮盈10%、N20、每窗口cap1全部保持冻结。
```

这不是推荐对每个标的独立选择九宫格中的**最高**值，而是：

- 检查邻近参数是否仍有类似CAGR、MDD、换手与交易结果；优先大片的“稳健高地”而非单一尖峰。
- 用交易窗口归因检查利润是否仅来自1–2个极端事件，是否依赖某一宏观年份。
- 验证相对相同资产的冻结H3、A、B和Buy&Hold是否有**真实账户**增益；仅胜率高不够。
- 手续费上调、开盘滑点、跳空压力、现金收益等敏感性单独重跑；防止小改善被摩擦吃掉。

### 阶段2：新形态先判断可学性，再提升为独立入场模块

候选公式必须以**时间顺序事件**为基础，例如：

```text
p: 某个过去完整日，EMA20[p] < EMA60[p]，差距/ATR_N很小
p之前：两线确实从更大差距向靠拢状态移动
p之后：EMA20从未成功上穿EMA60，自己掉头下降，线间差距再次扩大
t: 后续新的EMA10上穿EMA20，在t收盘后确认
执行: 仅研究假设为下一正常开盘买入
```

**先不把所有距离/窗口/掉头阈值做多维穷举**；优先看同类独立事件有多少、20/60日正向概率、实际FAST死亡交叉次开盘离场净收益、最不利价格、路径依赖和时间窗重叠。若像QQQ一样完整形态只有2笔，状态只能是 `INSUFFICIENT_EVENTS`，**不能选择2/2成功的最佳阈值**。

当另一个长期标的真正提供足够观察时，再另立版本加入**H3完整状态机**，测试允许特殊进场后的整账户CAGR、MDD和新增失利。新形态要有明确的失效时间、最近一次形态使用次数和与正常H3入场谁优先。不能用只看未来20天收涨的“成功概率”宣称可交易利润。

### 阶段3：单独验证A/B或B的特别买回必要性

先保证原版A/B重现，然后才独立验证 `special_reentry_enabled=false` 与原true的差异；B中历史12笔特别买回均相对不买回更差，值得研究，但**取消特别重入的完整资金账户是否更优需要单独复算**。新候选需要新ID，不是修改B v1.0。

### 阶段4：交互、仓位、运行监控

只有至少两个独立模块分别在外部验证有效，才跑组合交互；至少包含`H3`、`H3+入场模块`、`H3+B参数变体`、`H3+入场模块+B变体`，检验有无正或负交互。仓位规模与资金分配之后独立处理。

运行时需要：**数据质量闸门→完成信号计算→实际持仓与H3影子状态→订单意图→人工批准/通知→事后归因**。当前仓库默认只允许**信号/报告**；不得在没有单独授权和风险控制的情况下接通券商下单。

## 五、防止“针对标的调性”沦为过拟合：选择协议

1. **标签先行**：参数是否入场测试前写下阈值、样本起止、数据源、成本、成功标准和候选清单；未验证的新数据不得在看见后反向修改候选，再称其为样本外。
2. **时间顺序回测**：有足够长期数据时，用滚动或扩展式 train→validation→test，允许从过去学，不允许未来信息进入已执行交易。测试样本冻结，产生新参数就作为下一版本评估，不回填整个历史宣称“原来就会这样交易”。
3. **跨标的外检**：SPY与QQQ互相验证虽有帮助，但因为美国共同风险因子，独立性有限；可交易日经跟踪ETF、其他长期资产更适合检验泛化。某标的首次上市后的独立时期与未见过的未来数据更可靠。
4. **全账户多目标**：默认考虑账户MDD目标约20%–25%（仅历史风险预算、**非未来上限**）、CAGR、Calmar、Payoff、利润因子、单笔最差、连续亏损、交易费用、仓位利用率、现金机会成本和不同熊/牛阶段。一套参数若只是抓了一个暴涨窗口提升CAGR，不能自动获胜。
5. **交易样本不足就保守**：14个A/B分歧窗口、2个完整新形态都严重不足；哪怕统计比例达到100%也不能宣称普遍高胜率。
6. **参数不频繁重估**：建议年度或按预先约定的新增独立数据窗口进行批量重新验证，只有新证据足够才升级配置版本。运行中仅因市场波动当天变大就不断重选最优参数，是更复杂的**动态适应策略**，须单独验证、不能偷换为“针对标的调性”。

推荐**先定状态，再定参数**，并保留失败结果：

```text
IDEA -> EVENT_STUDY -> FULL_ACCOUNT -> CROSS_ASSET -> WALK_FORWARD
    -> PAPER_MONITOR -> REVIEWED_CANDIDATE
                           ↓
                   FAIL / INCONCLUSIVE / RETIRE
```

所有通过报告需要输出：行情来源/复权/哈希，参数版本与Git SHA，每个交易信号的`asof`，信号日/成交日，买入/退出理由，真实仓位与H3影子仓位，手续费、每天完整账户、最差回撤区间、发生变化的所有交易、参数邻域与独立时期结果、未采用的候选清单。

## 六、当前版本的研究实施顺序和分工

**现在优先**：对 SPY 与**一个确定且合法取得日线的可交易日经225 ETF**，先跑冻结H3、A和B三组母体，再独立跑B的9格ATR敏感性；将结果并排，不先进行任何“每资产最优配置”。

**以后第二批**：新形态从宽松到严格的事件频率检验；如果跨标的仍只有个位数事件，就保持其为监控标签，不给真实买入权限。

**以后第三批**：在已验证的标的上分别研究取消A/B重买、波动率状态和仓位分配；最后才考虑按资产选择不同参数及组合联合优化。

**v0.1 的边界**：这份文件和JSON只把模块接口、变量、依赖、执行、参数试验顺序、验证规则**正式固定**。**尚未写出统一跨标的可运行引擎，也没有声称SPY/日经的组合已回测或已得到专属最优参数**。下一次开发需先做独立数据适配和逐日对账，不改变既有冻结引擎。
